# 在线平台演进路线

## 目标架构

保留一套稽核规则、整改流程、专题分析和报表逻辑，通过适配层支持两种运行形态：

| 能力 | 本地模式 | 在线模式 |
| --- | --- | --- |
| 数据库 | SQLite | PostgreSQL |
| 文件 | 本机工作目录 | 服务端对象存储 |
| 身份 | 单机使用者 | 登录、组织、角色与数据权限 |
| 并发 | 单进程工作区锁 | 数据库事务、任务锁和幂等控制 |
| 交付 | Windows/macOS 可执行程序 | HTTPS 服务与持续部署 |

## 阶段一：运行边界

- [x] 默认运行模式明确为 `local`。
- [x] 无效运行模式启动失败。
- [x] 在线依赖未完成时，`APP_MODE=online` 明确拒绝启动。
- [x] 抽取数据库接口，业务流程通过仓储和数据库管理适配器访问 SQLite。
- [x] 抽取文件存储接口，以文件引用衔接上传、生成、发布和清理流程。

## 阶段二：多用户在线基础

- [ ] PostgreSQL 迁移、连接池和事务边界。
- [ ] 文件上传、下载、校验及对象存储。
- [ ] 用户、组织、角色和数据范围权限。
- [ ] 服务端会话、CSRF、防暴力尝试和安全响应头。
- [ ] 操作日志包含操作者、组织、请求来源和关联任务。
- [ ] 长耗时导入、稽核和导出进入后台任务。

## 阶段三：部署与迁移

- [ ] 本地 SQLite 与在线 PostgreSQL 双测试矩阵。
- [ ] 脱敏测试数据迁移演练及回滚方案。
- [ ] 备份恢复、监控告警和审计留存。
- [ ] 灰度环境验收后开放生产环境。
- [ ] 本地版继续可独立运行和打包。

## 阶段四：手机端

先提供响应式 Web/PWA，优先覆盖问题查看、整改填报、复核、进度和消息提醒。
只有明确需要系统推送、拍照扫码、深度离线或设备能力时，再建立原生或跨平台 App。
手机端只复用在线 API，不复制稽核与工作流逻辑。

## 当前配置契约

源码与桌面程序默认保持本地模式：

```bash
APP_MODE=local scripts/start.sh
```

现阶段设置 `APP_MODE=online` 会主动报错。这是一项安全保护；只有数据库、文件存储、
身份认证和授权适配器全部接入并通过测试后，才能解除。
